# 차량관리 최종 적용 기준표 v1.0

2026-09-06. 앱이 처음 제안할 관리 방식과 실행 조건을 항목별로 결정한 기준표다. 기존 연구의 후보·참고범위와 구별하여 `launch-defaults.json`을 적용 기준으로 사용한다.

## 확정한 운영 방식

- 222항목: 주기관리53 / 작업·사건연동29 / 측정판정교환138 / 구조별주기2.
- 거리·기간이 함께 있으면 먼저 도달하는 시점. 정비회차는 사용자 선택을 허용하고 실제 교환일·거리는 따로 보존한다.
- 장착/하위부품에 맞는 관리묶음을 선택하면 기본값을 제안한다. 기존 개인 기준은 유지하고 사용자가 수정할 수 있다.
- `앱설계예방값`은 이번에 결정한 제품 설정이다. 제조사 인용값과 섞지 않고 출처 원문 및 더 이른 기준을 함께 유지한다.
- 측정형 항목도 정기 관리에서 빠지지 않는다. 기본5만km/24개월, 제동·타이어·가스·고전압·차체 안전 계통은5만km/12개월에 관련 이력과 상태를 확인한다. 이는 추가 종합관리 예약이며 제조사 안전점검·증상 대응을 미루는 기한이 아니다. 매회 전체 부품 탈거를 뜻하지 않는다.

## 적용 순서와 비용

위험증상/리콜/법정조치 → 더 이른 실제차량 기준 → 사용자 기준 → 앱 기본값 순으로 알림을 판단한다. 오일1만km/12개월·ATF5만km는 요청한 값을 유지한다. 차량별 첫 냉각수 교환기간이 확인되면 최초 기준을 먼저 적용하고 이후 반복 기준으로 전환한다.

연구 참고값을 예방교환으로 선택한 항목은 정상 부품의 선제 교환 비용이 생긴다. 예를 들어 쇼바5만km는 원문8만km보다 이르며50만km까지 거리상6회 대신10회가 된다. 전체관리 묶음 선택 시 이 차이를 보여주고 사용자가 주기를 수정할 수 있게 한다. 공임 묶음은 추가 공임·잔존가치를 비교하고 이미 도래한 정비를 미루지 않는다.

## 이번 확정에서 반영한 원문 판단

- 체인은 공급사 일반 설명을 바탕으로15만km 예방계획을 선택하고, 해당 체인키트의 가이드·텐셔너·스프로킷을 연동했다. [Gates](https://www.gatestechzone.com/en/news/2025-06-chain-maintenance)
- 베어링은 공급사13.6~16만km 경험칙에서10만km 선제 계획을 선택했다. [MOOG](https://www.moogparts.com/en-eu/archives/blog/how-long-wheel-bearings-last.html)
- 브레이크디스크는 임의 주행거리 대신 해당 부품 MIN TH와 손상 조건으로 교환을 결정한다. [Brembo](https://asia.bremboparts.com/america/en/support/car/maintenance/minimum-brake-rotor-thickness-212337)
- NOx 센서는 전원·통신·오염 원인을 분리한 뒤 불량 교환하도록 정했다. [HELLA](https://www.hella.com/techworld/en/car-parts/auto-electronics/nox-sensor/)
- 검색에 나타난 Gates의 펌프2년/4만km와 호스5년/10만km 표는 **보증기간 표**였으므로 교환주기로 사용하지 않았다. [원문 표](https://www.gatesaustralia.com.au/utility/warranty-and-terms-of-sale/gates-warranty-on-applicated-automotive-products)

## 데이터·검증

`data/launch-defaults.json`: 전 항목 기본정책과 구체적인 교환 조건. `tests/launch-defaults.cjs`: 222항목 누락, ID 연결, 거리·기간, 리튬배터리 예외, 하위부품 제한, 정비회차,25년/50만km 범위 검증. 표와 JSON은 같은 결정 데이터에서 작성했다.

교환·청소·보충·검사는 각각 이력을 남긴다. 청소/검사로 교환 시계를 초기화하지 않으며 부분교환으로 다른 부품까지 새것 처리하지 않는다. 알림은1,000km 또는30일 남았을 때, 한국시간 오전9시대·동일회차 중복 방지라는 기존 명세를 유지한다.

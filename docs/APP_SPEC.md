# 앱 구현에 넘길 동작 명세

이 문서는 구현 명세이며 아직 동작하는 앱 기능 설명이 아니다.

## 차량과 기록

차명은 자유입력. 연료(가솔린/디젤/LPG/기타), 전동화(없음/HEV/PHEV/BEV), 과급, 변속기 구조, 구동방식, 타이밍 구동, 냉각회로, 보조배터리 종류를 단계적으로 선택한다. 모름을 허용하고 미장착과 구별한다. 기계식 AWD와 전기식 AWD는 별도이며 BEV에 엔진오일을 만들지 않는다.

차대번호·번호판·규격·부품번호·영수증·기존 메모는 개인 저장영역에 보존할 수 있어야 한다. 공개 기준 데이터와 분리하고 사용자별 접근제어·삭제·내보내기를 제공해야 한다. 현재 공개 저장소에는 실차 개인정보를 넣지 않는다.

영수증 사진은 항목·날짜·거리·비용을 추출해 **확인 대기**로 만든다. 사용자가 승인하기 전 원장을 변경하지 않는다. 동일 영수증 중복, 여러 차량, 교환/점검/청소/보충, 부품비/공임/합계, 부가세 중복을 확인한다. 알 수 없는 항목은 원문을 보존하고 매핑을 질문한다. AI 제공자·비용·이미지 보관/삭제·오류처리는 구현 설계에서 결정해야 하며 현재 외부 AI 전송을 설정하지 않았다.

## 거리 추정

오늘 이전의 **서로 다른 최근 3개 날짜의 실제 계기판 관측**을 사용한다. 날짜 정렬 후 `(마지막km-첫km)/(마지막날짜-첫날짜)`로 두 구간을 시간가중한 일평균을 계산한다. 같은 날 값은 임의 평균하지 말고 확인된 최신 관측 하나를 쓴다. 2개는 임시 저신뢰 추정, 1개 이하는 거리 예측 불가다.

예: 1월1일10,000 / 1월11일10,500 / 1월21일11,200이면 일60 km, 1월31일 예상11,800 km. 새 관측이 생기면 최근3개로 갱신한다. 앞의 두 구간 일평균 차이도 표시해 변동성을 알린다. 이 범위는 통계적 신뢰구간이 아니다.

계기판 역행·교체·단위변경·비정상 급증은 자동 보정하지 않고 확인대기로 둔다. 실제 주행거리는 예상치로 덮어쓰지 않는다. 장기 미입력일수와 예상임을 표시하고 마지막 관측30일 이후는 낮은 신뢰 표시,90일 이후는 거리 예정일 안내를 보류하는 앱 정책을 둔다. 날짜 주기 알림은 계속 계산한다.

## 정비 시계

부품·회로·좌우위치별 독립 자산을 둔다. 교환만 해당 교환 시계를 갱신하며 점검·청소·보충은 별도 사건으로 기록한다. 타이어 연령은 제조일, 일반 소모품 기간은 실제 교환일, 최초 규칙은 출고/해당 최초기준일을 사용한다. 중고 구입일을 미상 교환일로 대신 쓰지 않는다.

기본은 실제 교환거리+선택주기다. 회차 맞춤은 명시적 선택이며 가까운 후보만 제안한다. 실제49,500 / 선택50,000 / 주기50,000이면 목표100,000이다. 원문주기가50,000이면 원문도래99,500을 별도로 보이며 먼저 알린다. 기간은 실제 작업일부터 계산하고 월말은 대상월 마지막날로 맞춘다.

최초 냉각수200,000 km/120개월, 반복40,000/24개월처럼 최초·반복을 분리한다. 실제 조기교환이 확인되면 다음은 반복규칙이다. 이력 미상은 만료 여부를 단정하지 않고 확인 필요로 표시한다. 순서가 뒤바뀐 과거 기록과 취소/수정은 감사이력을 남겨 재계산한다.

## 알림

한국시간 매일 오전9시대에 확인한다. 실제 예약 서비스의 실행 오차를 허용하며 정확히09:00 보장은 하지 않는다. 남은 거리≤1,000 km **또는** 날짜상 기한/거리추정 기한≤30일이면 예정, 기한초과면 초과 상태다. 원문 기한과 선택 목표 중 이른 것, 거리·기간 중 이른 것을 사용한다.

자산+교환사건+규칙버전+상태단계로 중복을 막는다. 진입 알림과 초과 전환만 기본 발송하고 매일 반복하지 않는다. 재시도에도 같은 발송키를 유지한다. 규칙 수정으로 이미보낸단계가 바뀌지 않으면 재발송을 억제하고 사용자 설정 변경 요약으로 대체한다. 교환완료 확인 후에만 다음 회차로 이동한다. 서버가 필요하며 Codex 실행 여부에 의존하지 않게 구현해야 한다.

## 성향·비용

간편/균형/전체/직접선택은 추천 항목의 표시 범위를 바꾸며 주기·기록은 바꾸지 않는다. 사용자가 기록한 안전 이상은 묶음을 꺼도 보인다. 알려지지 않은 고장을 자동 감지한다고 주장하지 않는다.

공임 묶음은 관리성향 묶음과 독립이다. 사용자가 PK1만 켜도 실제 작업과 겹치는 선택적 예방부품을 설명할 수 있지만 자동 결제·교환기록 생성은 금지한다. 50만 km 예상 교환횟수·비용은 출발 이력, 거리율, 기간, 단가가 확인된 경우의 계획치로만 표시한다.

## 구현 검수에 남기는 항목

다중 사용자 격리, 백업복구, 영수증 실사진 인식 정확도, 모바일 화면, 알림 서버 재시도·중복방지, 실제 차량 규칙 매칭은 앱 구현 후 검증해야 한다. 이번 연구 검증의 PASS를 이 기능들의 PASS로 전용하지 않는다.
